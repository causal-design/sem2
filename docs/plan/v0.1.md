# SEM2 v0.1 implementation plan

**Documentation-only plan for PR #50, revised after the September 17 discussion.** The former scope document is now the [product specification](v0.1/README.md). It preserves the requirements, numbered decision agenda, and five detailed handoffs. This file specifies implementation units, order, affected files and functions, pseudocode, and review checks. No implementation or merge is authorized by this documentation update.

## Working agreement and minimality

- **Steps 1–5 are preparatory.** Implement and review them one at a time. Reuse the existing parser, model classes, operators, and trainer; do not use preparation as a reason to redesign the package.
- **Step 6 is separate and needs technical decisions before implementation.** The package-owned loop and required diagnostics are agreed; signatures, state handling, failure/result representation and numerical controls are not all settled.
- **Every new class or method needs a concrete justification:** which agreed requirement or real caller needs it, and why an existing method or a small function/record is insufficient. A suggested name here is not a mandate to create an abstraction. Avoid speculative base classes, registries, adapters, public wrappers, convenience getters, and general frameworks. The previously agreed support/named records have specific roles; do not surround them with more layers.
- **Scalar variables only in v0.1 fitting and examples.** A categorical variable with several levels is still scalar. Preserve existing low-level vector behavior only to avoid unrelated regressions; add no vector-valued DataFrame interface.
- **Categorical-to-numeric conversion is separate preprocessing before training.** Numeric-looking category labels do not establish quantitative meaning. Internal category encoding and deliberate numerical scoring are different operations. Carry supplied meaning/provenance; do not guess it or reconstruct unavailable preprocessing history from dtype.
- **Examples:** PoliticalDemocracy, Kang–Schafer adapted to the average treatment effect on the treated (ATT), the agreed binary two-stage experiment, and discrete-IV partial identification. There is no separate missing-data case study.

The source baseline inspected for this plan is `8269e91c3798956ebf94eed6209ff98643dac05a`. Existing names below are source starting points; proposed paths and names are marked as additions. Inspect fresh source before each implementation PR. Closed implementation examples linked from the product specification are not approved dependencies.

### Package documentation alongside implementation

Set up locally buildable Sphinx package documentation on top of PR #64; defer GitHub Pages and deployment automation. Document key components as their interfaces are implemented and reviewed; this is ongoing work within the relevant units, not an additional numbered step. Start with a small landing page and API reference, keeping the GitHub Wiki as a short entry point rather than a second copy of the package documentation. Unit 13 retains the final documentation, packaging, and release checks.

### Review rule for every unit

Each unit's PR contains only its bounded code, necessary caller migrations, focused tests, and a short usage/change note. Report actual execution. Do not add a class just to match this plan, and do not preserve a known incorrect result simply to keep an old test passing. Preparatory checks demonstrate construction, data flow and existing computations, not completion of fitting or causal estimation. Resolve changes to statistical meaning in the relevant technical review.

No whole existing source file is proposed for deletion below. Removal of duplicate definitions and obsolete payloads is explicitly identified; legacy file deletion needs an individual inventory and approval. New test filenames are proposed: extend a suitable existing test instead when that avoids fragmentation.

## 1. Correct model construction and formula semantics

**Purpose:** make existing formulas faithful before data and queries depend on them. This is preparatory repair, not a new formula framework.

**Files:** change `sem2/model/construction/{formula_parser,sem_ast,dag}.py`, `sem2/model/components/nodes.py`, `sem2/model/models/base.py`, and relevant cases in `tests/test_sem2.py`. No new source module or deleted file.

**Functions/classes:**
- Change `FormulaParser._parse_statement()`, `_lower()`, and `_expand_rhs()` to separate numeric intercept terms from parents and fix lifted summand coefficients.
- Add minimal intercept/helper-origin fields to the existing `EndogenousDecl`/`NodeSpec`, rather than a second AST or helper registry. Validate duplicate user definitions before dictionary construction can overwrite them.
- Pass fixed-intercept information through `SEM2._build_and_initialize_nodes()` to `NodeLinear.__init__()`, `bias()`, and `_forward_inner()`. Fixed values must not be trainable values merely initialized at the target.
- Use the same effective intercept in sampling and `SEM2Linear.mean_vector()`; change the latter only if the accessor alone cannot maintain consistency. Keep internal neural offsets outside this fix.

```text
parse linear equation:
    no standalone constant -> estimated intercept
    standalone number -> fixed intercept at that number
expand nonlinear summand -> private helper with fixed outer coefficient 1
preserve learned coefficients for ordinary bare predictors
validate names and duplicates; build the existing node types
```

**Checks:** zero/positive/negative intercept constants, mixed/nested expressions, fixed versus learned gradients, duplicate/helper-name rejection, consistency of sampled and analytical means. No new public node hierarchy.

## 2. Add only the required support and named records

**Purpose:** define the shared data contract before migrating callers.

**Files:** add `sem2/data.py` and `tests/test_named_data.py`; change `sem2/model/components/nodes.py` and only the necessary existing exports in `sem2/model/components/__init__.py` or `sem2/__init__.py`.

**Functions/classes:**
- Add the agreed `RandomVariableSupport` value record beside `RandomVariable` in `nodes.py`; expose inherited `support` with `constraint` and `values`. Delegate to existing PyTorch distribution/constraint information and small node-specific definitions, not another support framework.
- Add `VariableInfo`, `NamedBatch`, and `FiniteDistribution` in `data.py` for variable meaning, named draws, and enumerated states/probabilities respectively. These roles were already specified; use the smallest records that satisfy them.
- Implement named selection, row slicing, device transfer and finite marginalization only where required by callers in step 3. Do not add parallel getters or a public data-wrapper hierarchy.

```text
NamedBatch.select(names) -> columns in named order
NamedBatch.subset(names) -> same meaning in a smaller record
FiniteDistribution.marginalize(names):
    group states by retained coordinates; sum probability mass
```

**Checks:** ordering, retained supplied labels/scores, correct marginalization and autograd. Declared node support is not the set of observed values. Finite probabilities have separate exogenous-draw and state axes. Scalar public scope does not require deleting working low-level width information.

Extend step 2's tests. No new trainer engine or whole-file deletion.

**Functions/classes:**
- Change `SEM2.sample()` and `SEM2Discrete.sample()` to return named draws/finite distributions with the retained outer `(result, auxiliary)` convention.
- Migrate `PotentialOutcome.evaluate()`, existing scalar and linear operators, `DiscreteEnergyLoss` entry points and `DummyDiscreteDataloader.__iter__()` together. Adapt `_fit_batch()` only enough to consume the new record, without preempting step 6.
- Remove obsolete raw `states`/`full_state` auxiliary payloads, `p_true_mean` compatibility inputs, and positional legacy boundary formats; tensors remain normal inside numerical kernels.
- Repair discrete parent ordering, pre-coercion state validation, and intervention equation replacement. Add a small pre-allocation enumeration-size check in `SEM2Discrete.__init__()`.

```text

check state count before Cartesian-product allocation
for each node in topological order:
    use intervention value or evaluate declared ordered parents
return named draws or states paired with their probabilities

```

**Checks:** renamed/reordered variables, probability normalization, invalid fractional/unknown states, both sampler forms, unchanged gradient paths, rejection of retired boundary inputs. Any necessary numerical correction is isolated and explained; pending estimator choices remain pending.

## 4. Implement public DataFrame preparation

**Purpose:** one private preparation path for `fit` and direct trainer use; observation status belongs to the model/data pairing.

**Files:** change `sem2/data.py` and, only if needed to expose user-declared identities, `sem2/model/construction/dag.py`; add `tests/test_data_preparation.py`; add pandas consistently to `pyproject.toml`/`requirements.txt`. No new public wrapper or deleted file.

**Functions/classes:** add a small `prepare_data()` function with private normalization/validation helpers only where needed. Return the existing named record plus a small report; **do not require a new `PreparedData` class**. Reuse `_DAG` node identities, excluding compiler-generated helpers. Do not mutate the structural graph or force users to write `unobs(...)` for fitting.

```text
require DataFrame; copy without mutating caller
normalize column names deterministically; report mapping
match to user variables; reject unknown or duplicate names
validate scalar variables and supplied quantitative/categorical meaning
retain complete cases; report input/retained/dropped counts
encode category identities without assigning scores
return named data + preparation report
```

**Checks:** reordered columns, collisions/duplicates, unsupported vector cells, no retained rows, no silent drops, no caller mutation, category codes versus deliberate scores. A categorical node's several output probabilities do not make the variable vector-valued. Specify the small supplied-meaning/provenance carrier before implementing it; do not infer erased external history.

## 5. Prepare objective composition using existing operators

**Purpose:** let the existing trainer consume an objective without embedding the scientific target in training flags. The user identified this as preparatory work; final public argument selection belongs to step 6.

**Files:** change `sem2/operators/{scalar_operators,linear}.py`, affected `sem2/default_configs.py` fields/callers only as needed, and add `tests/test_objectives.py`. No new base class, registry or optimizer.

**Functions/classes:** adapt `SEM2Loss.__init__()`/`evaluate()` to accept the existing scalar components and weights; keep metric names distinct. Reuse `LogLikelihood`, `SEM2LinearModelOperator`, and `WeightedFrobeniusDistance` with prepared observed names. Prefer a simple component list over a new loss specification class. Preserve current caller functionality while step 6 chooses the public objective argument.

```text
for existing operator and weight:
    value, component_details = operator.evaluate(named_data)
    add weighted value; retain separate component details
return scalar objective and diagnostics
```

**Checks:** named Gaussian calculation and gradients, distinct diagnostics, and a small composed objective. `LogLikelihood.evaluate()` currently returns mean log-likelihood; negative mean log-likelihood is the proposed minimization convention, to confirm with step 6. This does not approve pending energy estimators or introduce a new discrepancy family.

## 6. Canonical trainer and public fit — separate technical review

**Purpose:** finish formula → DataFrame → fit → diagnostics only after the trainer decisions are reviewed. Completing preparation does not authorize implementing this step automatically.

**Files:** change `sem2/sem2trainer.py`, `sem2/default_configs.py`, `sem2/__init__.py`, and `experiments/{trainer,train}.py`; add `tests/test_trainer.py`. Remove duplicate `SEM2Trainer` and `get_optimiser` definitions from `experiments/trainer.py` after migrating its example to the package; retain the file as a demo, not another engine.

**Functions/classes:** add thin public `fit()`; change existing `SEM2Trainer.__init__()`, `train()`, `_fit_batch()` and `get_optimiser()` as needed. Return the model, preparation report and required diagnostics in the smallest reviewed representation. **A new `FitResult` class is not required**; choose between an existing/simple record and a small value class only for a concrete benefit. No public `step` API.

**Decide before implementation:**
1. The accepted objective argument and Gaussian minimization convention; `fit` and direct trainer must agree.
2. Whether ordinary fitting mutates the supplied model and how repeated fits reset/reuse optimizer state. Preserve the sweep's separate fresh/warm-start agreement.
3. Seed handling, batch size and independent model-draw count; apply each objective's valid-batch rules.
4. History cadence/aggregation and final-evaluation observations/draws.
5. Failure transport and retention of settings/partial history, including what a sweep can inspect.
6. Minimal result shape and optional loss-plot entry point, without a diagnostics framework.

These refine, not reopen, the [agreed trainer requirements](v0.1/minimum-fitting-interface-and-diagnostics.md).

```text
prepare once; construct reviewed optimizer and objective
for prespecified epochs and valid batches:
    clear gradients; evaluate; reject nonfinite loss
    backward; check/record raw gradient norm; update
    retain detached history and separate data-fit diagnostics
evaluate final loss after the last update
return model, reports, completed updates and honest termination reason
```

**Checks:** equivalent public/direct routes, final evaluation on returned parameters, finite histories, failed runs not marked successful, no convergence claim for budget completion. Test a small real Gaussian fit, not a fake objective or fabricated training result. No validation loop, automatic stopping or cross-fitting.

### 9b. Kang–Schafer adapted to ATT

**Files:** add `experiments/kang_schafer.py`, `tests/test_kang_schafer.py`, and `docs/confounder_adjustment.ipynb`. A bounded change to existing `MeanPotentialOutcome`/`PotentialOutcome` methods in `sem2/operators/{scalar_operators,vector_operators}.py` is conditional on an approved need; default to an example-local estimator function. No mandatory `ATT` class, missing-data module, or general conditioning framework.

**Functions/classes:** propose `simulate_kang_schafer()`, `build_model()`, `estimate_att()` and `run_example()` as ordinary example functions. Put an independent truth/reference calculation in the test/example code, not in training. Use the source's covariate/assignment structure and label exactly how the outcome generator is adapted.

**Agreed:** an ATT problem, with observed factual outcomes and no separate missing-data case study. ATT averages the treatment-versus-control potential-outcome difference in the population whose factual treatment is treated. It is neither the population ATE nor the naive observed treated/control mean difference.

**Still needs a bounded design review:** specify both potential outcomes, treatment levels, observed versus generator-only covariates, adjustment/overlap assumptions, how the treated covariate distribution is represented, and whether evaluation averages over observed treated covariates or a fitted treated-population law. Distinguish sample-treated from population ATT references. Review a minimal ATT evaluation method without treating intervention as conditioning. No new numerical effect size or generator is approved by choosing the example family.

```text
simulate covariates, factual treatment, and both potential outcomes
expose only factual outcome and agreed observed covariates to fitting
fit once with the approved continuous-energy objective
estimate both regime outcomes for the same factual-treated target population
average their difference using the reviewed ATT procedure
compare with an independent reference for that same target
```

**Checks:** no generator-only information reaches fitting; covariate dependence is preserved; both treatment arms inform adjustment where needed. Include a reviewed heterogeneous-effect check where ATT differs from ATE, so a population-average implementation cannot pass accidentally. A constant-effect case alone does not test treated-population conditioning. Depends on 7–8 plus this adaptation review; ordinary ATE remains unchanged.

## Remaining decisions and evidence boundaries

Earlier links to the former plan's decision agenda can now follow the [preserved numbered product agenda](v0.1/README.md#next-steps-and-review-decisions).

- **Before step 6:** the trainer technical choices listed there; preserve its already agreed minimum behavior.
- **Before step 7:** energy/discrete/IV mathematical choices, not a new discrepancy family.
- **Before 9b:** the concrete Kang–Schafer ATT adaptation and smallest valid treated-population evaluation. ATT and no missing-data case study are settled; the method is not.
- **Before 12:** selector details; the broad contiguous-window approach is settled.
- **Before public data/query/preprocessing integration:** the minimal supplied-meaning/provenance carrier and categorical-query failure/event-scoring behavior. Do not reopen whether scoring is separate preprocessing.
- **Documentation/packaging:** format preview, optional graph preview, dependency arrangement and individual legacy deletions remain as recorded in the [product agenda](v0.1/README.md#next-steps-and-review-decisions).

No `PreparedData`, `FitResult`, `PenaltyRun`, endpoint, or `ATT` class is mandated by this plan. Additional classes/methods must earn their place in review. Steps 1–5 do not authorize starting step 6 or the paused identification/search work. Each unit still requires a fresh implementation request and human review; approving PR #50 does not approve code, integration or release.

The existing PoliticalDemocracy source is [the integration test](../../tests/test_political_democracy.py) and its local data. The primary external references are [lavaan's model example](https://lavaan.ugent.be/tutorial/sem.html) and [Kang–Schafer, section 1.4](https://arxiv.org/pdf/0804.2958). The latter is an original population-mean/missing-outcome simulation; the ATT treatment example is an agreed adaptation, not a claimed verbatim reproduction. No new ATT generator, fitter, selector, package test or numerical recovery has been executed by this documentation change.
