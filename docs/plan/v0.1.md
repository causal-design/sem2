## Supported models and example-level acceptance

| Model/example family | What v0.1 must demonstrate |
|---|---|
| Linear Gaussian SEM | Fit linear models, including a measurement-model example; check coefficients and moments against known values and use appropriate OLS/lavaan comparisons. |
| Discrete IV | Fit small finite-discrete IV models, including a ternary-treatment contrast. Apply strict instrument-level eligibility; compare numerical search endpoints against test-only LP/Balke–Pearl references for the same observed table and assumptions. Report numerical accuracy for manual review, without a predeclared bound-recovery threshold. Integrate the supplied extrapolation work through a native sweep and postprocessor; only automatic window-selection details await agreement. |
| Basic confounder adjustment | Fit a simulated model using the continuous energy-loss route and estimate a causal contrast whose value is known from the simulation. |
| Two-stage sequential randomized experiment | Represent two treatment stages and intermediate information potentially confounded with the outcome. Evaluate named joint interventions and check the chosen causal contrast against simulation truth. |

Use a small CPU-run collection, not a large simulation grid. Humans review the reference cases and numerical tolerances where applicable; discrete-IV bound-recovery accuracy is diagnostic rather than a predeclared pass/fail threshold in v0.1. These examples cover F15/F16/F25/F32/F34/F35/F40/F44 in the decision record.

## User workflow and data handling

- For ordinary fitting, specify the model and named data, choose the objective and epoch budget, and call `fit`; the package owns the loop. Return inspectable loss/gradient history with an optional training-loss plot, keeping gradient detail out of the default plot. Then sample or evaluate named treatment/outcome queries without refitting solely to change the query.
- Check graphical identification within the agreed single-margin scope. On success, skip a bound search by default; estimation may still need fitting. On non-identification, warn and suggest an explicitly requested, query-specific numerical search. Unsupported inputs are errors, not non-identification results.
- For partial identification, specify the target before optimizing its signed contribution alongside observational fit. Report numerical lower/upper search estimates and separate fit diagnostics, not automatically sharp bounds or confidence intervals. Run only user-supplied penalties, using fresh starts by default or an explicit warm-start option, and pass native results to a separate automatic contiguous-window postprocessor. Regress ATE on signed penalty toward zero, separately for positive/lower and negative/upper searches. No generated grids, ordinary-use selector tuning, CSV compatibility adapters, or resumability are required; ordinary query evaluation must not silently start training.

Follow the [agreed minimal model–data handoff](v0.1/minimal-model-data-interface.md) for F02/F03: require user-supplied pandas DataFrames (reject other input types clearly; no automatic format conversion), direct column/model name matching, automatic internal preparation, dataset-relative observation status, and complete cases with explicit reporting. `fit` is a convenience layer over one canonical Trainer, not a separate training engine. The handoff also records estimated intercepts by default, numeric constants fixing their values (`0` means no intercept), and correctness fixes to the existing parser expansion. Implement the richer dataset schema in v0.2; advanced missing-data handling is deferred until after v0.2.

Retain both finite-discrete fitting through `SEM2Discrete` and deliberate numeric treatment through base `SEM2`. Provide an explicit categorical-to-numeric conversion helper, analogous in purpose to R's `as.numeric` (F28). The chosen numeric representation is a modeling decision, not equivalent to finite-discrete fitting. Review the helper's name, placement, and conversion rules; do not expand it into the general preprocessing framework deferred under F09.

Across the package, retain original categorical status, labels, and mappings after both internal encoding and deliberate categorical-to-numerical conversion. Record any user-supplied numerical interpretation. Do not silently use category codes as numerical outcome values for ATE: warn and suggest a distributional estimand or deliberate numerical conversion when that interpretation is absent. Let users choose treatment levels and contrast direction, such as ATE for `2` versus `0`, in ordinary queries as well as numerical searches. These are general requirements, not IV-specific features; see the [general variable and estimand decisions](v0.1/identification-and-partial-identification.md#general-design-requirements-for-variables-and-estimands).

For discrete-IV fitting specifically, require at least two retained complete-case observations per declared instrument level; otherwise stop before fitting and warn with the counts. Do not silently drop/merge levels or add pseudo-counts. Validate full-data eligibility separately from minibatch safety.

The ID check concerns the supported graphical problem; it does not establish identification from extra parametric/proxy assumptions. Data fusion and latent-variable targets are outside its v0.1 scope. State the checked interventional distribution: its non-identification does not automatically prove every scalar functional nonidentified. The numerical experiment checking whether lower/upper estimates coincide is deferred; coincident numerical estimates are not an identification proof.

### Unit tests

Keep these in [tests/](../../tests/), separate from the four example-level acceptance cases:

- Named data mapping, retention of category meaning after internal and explicit numerical conversion, tensor shapes, loss values/gradients, and basic trainer diagnostics.
- Finite-state probability calculations and the enumeration guard.
- Intervention equation replacement, unaffected mechanisms, renamed nodes, multiple treatment names, and user-selected contrasts such as `2` versus `0`, including a non-IV example.
- Graph projection and ID results on reviewed reference graphs, including unsupported-input handling.

For F34/F35, keep a few focused binary/non-binary IV checks, including a ternary-treatment contrast, category-provenance warnings, and absent/singleton instrument levels. Use independent LP/Balke–Pearl calculations only in tests under standard IV assumptions without silently adding monotonicity or linearity. Keep the observational loss separate from the signed estimand term in diagnostics, and report counts, total variation, and largest cell-probability error to users. Cover both initialization modes and the native sweep/postprocessor boundary. After selector agreement, check chosen points and intercepts on a small clean/flat/bent-end/weak-input set. Numerical recovery/stability is reviewed manually, not against a new v0.1 accuracy threshold; see the handoff for the exact interpretation limits.

Regression tests must run independently of documentation notebooks. Shared example-generating code is fine.

## Completion and limits

v0.1 is ready for review when the package installs with separated dependencies, all four examples and the relevant correctness tests run successfully on CPU, numerical checks meet their agreed review criteria, the documentation builds, and the retained notebooks run. Discrete-IV bound-recovery accuracy remains a manual diagnostic, not a predeclared tolerance gate. The detailed automatic selector must be agreed, implemented, and exercised before claiming completion; the supplied experimental function and this documentation do not establish that outcome. Users must be able to inspect fitting diagnostics and understand the assumptions behind query results. Human acceptance of the milestone is separate from a public release.

Beyond the stated richer dataset schema, v0.1 excludes broad preprocessing, a new general vector-valued-node framework, new discrepancy families, robust multistart/continuation machinery, general uncertainty quantification, proximal/RDD examples, graph discovery, and GPU/HPC infrastructure. Preserving existing vector widths during the named-data migration does not expand that scope. The decision record retains their individual priorities; this plan does not require a new CI pipeline or release process.

Validation-loss monitoring, automatic stopping/best-iterate restoration, estimator-specific cross-fitting, and a public `step`/`evaluate` interface are [possible future extensions](v0.1/minimum-fitting-interface-and-diagnostics.md#possible-future-extensions--unscheduled), not commitments to a particular release. Keep the v0.1 trainer small; do not make these extensions milestone prerequisites.
