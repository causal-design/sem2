## Meeting purpose

The meeting had three aims:

1. bring the group to a shared understanding of the software and mathematical work completed so far;
2. identify the next software and theoretical priorities; and
3. discuss whether neural-process or PFN ideas could extend the current point-estimation framework.

## Overall position reached

SEM2 already has a coherent model-building core for fixed directed acyclic graphs. A formula declares exogenous distributions and endogenous structural assignments; the package parses the formula, builds a DAG, creates executable node modules, and can sample observational or model-interventional distributions. Linear Gaussian, nonlinear continuous, and finite discrete cases have been explored, but their fitting paths are at different stages of maturity.

The group did not treat observational fit as sufficient for causal identification. Two separate questions remain: whether the causal quantity is identified under the graph and observational regime, and whether that quantity is regular or smooth enough relative to the chosen discrepancy to support stable estimation and uncertainty quantification.

The clearest architectural decision was to stop treating observed versus latent status as an intrinsic property of the structural model. A variable can be observed in one dataset and absent from another. Observation status should therefore belong to a dataset-to-model mapping or to an operator that combines a model with data.

PFNs were accepted as a worthwhile research direction, but the discussion narrowed the sensible scope. Learning a posterior or causal quantity for a supplied graph appears more defensible than asking a transformer to output a graph. The farther the amortization extends across graph structures, the more useful it could become, but the greater the sensitivity to the simulated prior and the harder the identification and generalization problem.

## 1. Statistical model and formula language

### 1.1 Structural setup

The intended workflow starts from a formula that describes both the graph and the supported structural mechanisms. The formula records:

- exogenous nodes and their distributions;
- endogenous nodes as deterministic functions of their parents;
- linear coefficients, including coefficients fixed by the user;
- nonlinear mechanisms represented by neural networks;
- finite discrete mechanisms; and
- in the current implementation, a declaration of unobserved nodes.

Exogenous variables supply the stochastic innovations. Endogenous variables are deterministic once their parents, including exogenous parents, are fixed. This differs from notation in which each endogenous equation contains an unnamed error term: SEM2 represents that error explicitly as an exogenous node. The exogenous distributions must still be declared. In a sufficiently flexible nonparametric construction their choice may act mainly as a reference-noise normalization, but that equivalence was not formalized in the meeting and should not be assumed for restricted model classes.

The formula determines a topological evaluation order. A model can then generate samples by drawing the exogenous variables and evaluating the endogenous assignments in that order.

### 1.2 Meaning of "semiparametric"

The group discussed the label *semiparametric*. A purely linear specification is parametric. A specification that combines explicit finite-dimensional components with high-capacity neural mechanisms has a semiparametric or nonparametric motivation, although any fixed neural-network architecture remains finite-dimensional. The useful practical distinction is that some scientific parameters are explicit path coefficients, while other quantities, such as means, quantiles, or treatment effects, may need to be computed from the fitted generative distribution.

Sample generation does not make every functional equally accessible. Means and quantiles can be estimated from generated samples. A pointwise density value, for example, requires additional smoothness or density-estimation structure.

### 1.3 Observed and latent variables

The current formula syntax can mark variables as unobserved. The meeting concluded that this is conceptually misplaced.

A structural model describes the system. Observation status describes how a particular dataset views that system. The same variable may be observed in one study and absent in another, and two datasets with different observed margins could inform the same model. The model needs exogenous/endogenous status, but it should not need a permanent observed/latent partition.

The proposed separation is:

- the formula and DAG define nodes, edges, distributions, and structural equations;
- a dataset schema maps table columns to model nodes and states which model variables are observed in that dataset; and
- a fitting operator combines one or more dataset views with the model.

This change also clarifies why potential-outcome and loss operators need named treatment, outcome, and observed variables even when the base model does not. It does not make extremely sparse observation designs easy: a dataset that observes only a few nodes in a much larger latent system may still be severely over-parameterized or computationally infeasible.

### 1.4 Multiple data sources

The group considered fitting one model to several datasets with different observed margins. The corresponding losses could be added with appropriate scaling, especially when sample sizes differ. The same framework could combine observational and interventional datasets by giving each dataset its own observation map and regime.

This capability is not implemented. It depends on a proper data layer, column-to-node mapping, and explicit loss weighting. No participant saw a conceptual obstacle in the model framework itself.

## 2. Estimation objectives and loss functions

### 2.1 Common fitting target

Across model classes, fitting was described as choosing model parameters so that the model-implied distribution on the variables observed in a dataset agrees with the empirical distribution. The criterion may be an exact likelihood, a moment discrepancy, or a simulation-based distributional loss.

An additional scalar term can encode regularization or a scientific target. In the discrete instrumental-variable work, this mechanism is used to search among observationally compatible models for small and large values of a causal estimand.

### 2.2 Linear models

For linear Gaussian SEMs, the model-implied likelihood can be written exactly from the implied mean and covariance. This gives a deterministic objective without simulation noise. Linear non-Gaussian models have also been considered, but the fitting route depends on whether a tractable likelihood or another suitable discrepancy is available.

The meeting noted that a simple one-parameter linear example should use a reliable optimizer or a closed-form solution where possible. L-BFGS with a closure was reported to converge faster and more tightly than the rough Adam loop shown in the earlier review. More generally, the package needs robust optimizer wrappers and convergence diagnostics rather than ad hoc loops copied into examples.

### 2.3 Nonlinear continuous models

The main current idea is to sample from a differentiable structural model and compare generated and observed rows with a distributional score.

Energy score is implemented as the general-purpose route discussed in the meeting. MMD and Sinkhorn divergence were considered as alternatives:

- MMD is relatively easy to compute, but participants described training runs that can make little progress once generated and observed distributions are roughly aligned.
- Wasserstein geometry can provide a stronger movement signal for individual generated points, but exact optimal-transport calculations are harder.
- Sinkhorn divergence interpolates between these ideas and may offer better optimization behavior at manageable cost.

A contributor reported a local Sinkhorn implementation and preliminary heavy-tail experiments in which Sinkhorn appeared to perform better than MMD. This was an observation from ongoing work, not a settled benchmark or theoretical result. Possible explanations discussed included the different geometry of the losses and the influence of observations far from the bulk. The contributor also wondered whether MMD was extracting little beyond a few moments in those runs and whether winsorization might produce similar behavior; this was speculation, not a demonstrated mechanism. More experiments are needed.

The Sinkhorn and regression-discontinuity study code was not in the shared repository at the time of the meeting. The contributor agreed to prepare it for repository review.

### 2.4 Projected and sliced scores

Sergio raised projected or sliced energy scores as a response to poor high-dimensional scaling of the ordinary energy score. The idea is to project multivariate observations onto many one-dimensional directions, compute a one-dimensional score in each projection, and average the results. Sliced Wasserstein methods were mentioned as closely related.

The group agreed that this deserved investigation. The exact method, terminology, references, statistical properties, and computational tradeoffs were not settled during the meeting.

### 2.5 Finite discrete models

The finite discrete route calculates probabilities over configurations rather than relying on ordinary differentiable samples. This supports exact finite-state calculations and is useful for toy causal and partial-identification problems.

Not all discrete research code had reached the main repository. One contributor said that most, but not all, of the separate implementation used for a paper was present. A general discrete likelihood had not been implemented.

The meeting reviewed three broad ways to handle discrete nodes:

1. enumerate finite states and propagate probabilities exactly;
2. use a continuous relaxation that lets an energy-type loss push outputs toward supported discrete values; or
3. use a reparameterized device such as Gumbel-Softmax.

The reported discrete work used a direct probabilistic approach rather than Gumbel-Softmax. Exact enumeration is useful for calculations and small examples, but it narrows the practical scale because the state space grows quickly.

## 3. Partial identification and causal computation

### 3.1 Discrete instrumental-variable bounds

The meeting used a discrete instrumental-variable graph as the main example of partial identification. With an unmeasured variable and discrete instrument, treatment, and outcome, the observational distribution may leave many causal data-generating distributions compatible with the data. The causal effect can nevertheless lie in a nontrivial interval.

The computational strategy is to fit the observed distribution while adding a small positive or negative multiple of the average treatment effect to the objective. Repeated optimization in opposite directions searches for observationally compatible models with large and small effects. The target can be simulation-based rather than an explicit coordinate of the parameter vector.

The group linked these discrete constraints conceptually to instrumental inequalities and Bell-type inequalities. It did not claim that a numerical extremum from one optimization run proves a sharp identified bound. Restarts, fit tolerances, optimization checks, and a sharpness argument are still needed for that conclusion.

### 3.2 Interventions in the model

SEM2 can replace a structural equation by setting a node to a chosen value and then propagate the remaining equations. Once a graph is accepted as causal, this operation generates a model-implied interventional distribution. An average treatment contrast can be calculated by setting treatment to two values, simulating outcomes, and taking the difference in means.

The participants stressed the conditional nature of this interpretation. Equation replacement computes what the specified model says under an intervention. It does not show that the graph is correct, that the exogenous assumptions are credible, or that the intervention distribution is identified from the available observations.

### 3.3 Identification and regularity are separate

Two problems were separated:

- **Identification:** whether the observational regime and causal assumptions determine the target, either as a point or as a set.
- **Regularity relative to the fitting criterion:** whether changes in the fitted distribution, measured by likelihood, energy score, Sinkhorn divergence, or another discrepancy, control changes in the target smoothly enough for stable estimation and inference.

A causal target could be structurally identified but poorly behaved under the chosen loss. Conversely, a computational intervention operator can exist even when the target is not observationally identified.

The suggested practical default was to seek bounds when point identification is doubtful rather than force a single causal estimate.

## 4. Uncertainty and theory

The current package primarily returns one fitted distribution and point estimates calculated from it. It does not yet supply confidence intervals or a developed uncertainty theory for nonlinear SCM functionals.

One proposed route is semiparametric theory: impose enough smoothness for the target to be differentiable, derive an influence function, and establish asymptotic normality under favorable conditions. The group acknowledged several limitations:

- the required smoothness assumptions may be strong;
- many assumptions cannot be checked from the observed data;
- partially identified targets need uncertainty for a set rather than an ordinary interval around a point; and
- a theorem for a well-behaved identifiable case may not address the hard latent-variable problems that motivated the project.

The project lead still regarded confidence intervals and theoretical guarantees as an important research task. The discussion also accepted a more pragmatic aim: characterize the range of causal conclusions among generative models that fit the observed data well, with transparent assumptions and without overstating formal guarantees.

A Bayesian treatment was discussed as a possible alternative or complement. Posterior credible intervals do not remove the need to justify the prior, the structural model, or identification.

## 5. Software architecture and interface

### 5.1 Current architecture

The architecture described in the meeting was:

```text
formula
  -> parser and typed statements
  -> DAG and topological order
  -> executable exogenous, linear, neural, and discrete nodes
  -> SEM2 / linear / discrete model class
  -> scalar or vector operator
  -> optimizer or trainer
```

`SEM2` is the general structural sampler. The linear subclass adds exact coefficient and covariance calculations and likelihood-based fitting. The discrete subclass handles finite-state probability calculations. Operators map a model, or a model plus data, to a loss, discrepancy, potential outcome, ATE, or another scalar/vector quantity.

The terminology around node types was recognized as somewhat inconsistent. The conceptual distinction remains clear: exogenous nodes have distributions, while endogenous nodes implement structural functions.

### 5.2 Missing data abstraction

The main interface gap is data management. The package lacks a single structure that records:

- table column names and their model-node mapping;
- observed variables for each dataset;
- treatment and outcome roles for a query;
- observational versus interventional regime;
- shape, dtype, support, and missing-value rules; and
- weighting when several datasets contribute to one fit.

Some current code relies on hard-coded names such as treatment `T` or benchmark variables. This is a symptom of the missing data contract. The group suggested a dedicated file or module for dataset handling.

### 5.3 High-dimensional usability

A long formula may be acceptable for a low-dimensional model but cumbersome for high-dimensional systems. The formula interface may eventually need programmatic graph construction, schema tools, or higher-level design-specific wrappers.

Convenience subclasses for standard designs, such as instrumental variables, could ask users only for treatment, outcome, instrument, and confounder mappings. This would improve usability without changing the core structural representation.

### 5.4 Graph comparison and discovery

The present system assumes a supplied graph. Fitting and comparing several candidate graphs, or testing model restrictions, was described as future work. Structural discovery has not been implemented.

The project motivation is to let applied researchers state the graph they believe is scientifically reasonable without being limited to a small catalogue of designs chosen for historical or computational convenience. For that reason, reliable fixed-graph fitting remains the nearer-term priority.

## 6. Review of the earlier examples

The first example in the AI-generated review fixed every relevant coefficient and only sampled or intervened. Participants found it too simple because there was nothing to estimate.

The one-coefficient linear fit was closer to the intended workflow: generate or load a table, leave one coefficient free, optimize a likelihood, and recover an estimate. Its presentation still raised questions:

- it used a rough manual Adam loop;
- it did not make clear whether a trainer wrapper already existed;
- the estimated coefficient looked less accurate than expected without optimizer diagnostics; and
- it did not connect fitting to a subsequent model query.

The updated example should therefore show one end-to-end path: construct a model with a free parameter, fit it to a named table, report the fitted coefficient and objective, and use the fitted model for an intervention. The example must remain a deterministic API illustration, not evidence that the estimator is accurate in general.

The finite discrete example correctly illustrates exact probabilities but remains limited to toy state spaces. It should make the enumerated support and any intervention contrast explicit.

## 7. PFNs and neural processes

### 7.1 PFNs as amortized Bayesian inference

Sergio described neural processes as specific to regression-style datasets and PFNs more generally as amortized Bayesian inference. Start from a prior and simulator:

```math
\theta \sim \pi,
\qquad N \sim p_N,
\qquad Z_i \mid \theta \sim P_\theta,
\quad i=1,\ldots,N.
```

A neural posterior approximator with parameters $`\phi`$ maps a variable-size dataset $`(Z_1,\ldots,Z_N)`$ to a distribution over $`\theta`$. It is trained on simulated pairs of parameters and datasets with a proper scoring rule. At the population optimum, if the output family is sufficiently expressive and optimization succeeds, the target is the posterior induced by the chosen prior and simulator.

A transformer is a natural architecture because it can process datasets of varying size. The output head could describe a normal approximation through a mean and covariance, or a more flexible distribution when skewness, heavy tails, or multimodality matter.

After training, a new dataset can be passed through the network in one forward evaluation rather than running optimization, MCMC, or variational inference for that dataset. This is useful only if the cost of PFN training can be amortized over enough future datasets or related tasks.

### 7.2 Relation to current SEM2 fitting

Current SEM2 fitting maps a dataset to a point estimate by solving a new optimization problem. A PFN would learn a dataset-to-distribution map in advance.

If SEM2 eventually supplies a point estimator and an estimated asymptotic variance, a normal or Laplace approximation could be constructed directly. A PFN is more attractive when the finite-sample posterior is not well represented by that approximation. It does not add value merely to reproduce an available Laplace calculation.

The existing point-estimation code might still help define simulators, summaries, baselines, or training targets. The meeting did not settle whether it could serve as a useful warm start for PFN training.

### 7.3 Priors are the central modeling problem

Normal priors on coefficients in a linear SCM were regarded as at least interpretable. Priors on the raw weights of a multilayer perceptron are much harder to defend because their induced prior over structural functions may not express meaningful scientific beliefs.

The PFN learns the posterior under the simulation prior. It does not learn a universally valid prior from exposure to many datasets. A poor function prior or graph prior remains a modeling problem, and simulation coverage does not remove it.

### 7.4 Proper-score guarantee and its limits

The proper-scoring-rule argument identifies the target of the ideal population optimization. It does not guarantee that a finite transformer, finite simulation budget, or practical optimizer will reach that target.

Sergio reported theoretical skepticism based on related work on transformers for ridge regression: even modest shifts from the training prior can cause poor generalization. This risk grows as the PFN is asked to cover more model and graph variation. Calibration under the training simulator is necessary but does not establish reliability under prior or structural shift.

### 7.5 Amortize the causal quantity rather than all parameters

A narrower proposal was to predict the posterior distribution of a causal response or perturbation effect directly instead of learning the full posterior over every SCM parameter. Training would simulate a context dataset and a target intervention or counterfactual query, then score the predicted distribution of the resulting causal quantity.

This may be easier because the output is lower-dimensional and aligned with the scientific target. It also resembles PFN regression, where a context set is used to predict a response distribution at target inputs.

The group noted related workshop work that generated random SCMs, random graphs, and random structural functions, then trained a transformer to predict counterfactual or interventional outcomes. The reported experiments reached roughly 35 nodes and 1,000 observations. Another output in that work was a pairwise edge probability rather than a coherent full graph.

### 7.6 Levels of amortization

The discussion separated four levels:

1. **No amortization:** fit each dataset and graph separately, as SEM2 currently does.
2. **Fixed graph:** train one posterior approximator for repeated datasets under a supplied graph.
3. **Graph as input:** condition one amortized model on both the dataset and a user-supplied graph.
4. **Graph as output:** infer graph structure as part of the output.

A fixed-graph PFN is the simplest and most defensible, but its training cost pays off only if the graph recurs across many datasets. Taking the graph as input better matches SEM2's goal of supporting user-specified structures, although it broadens the simulation and generalization problem.

The group considered graph-as-output learning overambitious for the present project. Markov equivalence, latent variables, and other non-identifiability make a posterior over graphs difficult to learn and interpret. Pairwise edge probabilities can be useful for discovery, but they need not correspond to a coherent graph and depend strongly on graph priors and regularization. Without a sparsity or structural prior, a fully connected graph can absorb many distributions and becomes a default unrestricted explanation.

The working direction was therefore to explore graph-as-input amortization, or a fixed-graph causal-query PFN first, while leaving graph discovery as a separate and lower-priority research problem.

## 8. Decisions and working agreements

1. **Move observation status out of the structural model.** Observed/latent status should be represented by the dataset mapping or the operator that combines data with a model.
2. **Bring external implementations into reviewable repository branches.** The local Sinkhorn/RDD work and the remaining discrete implementation should be pushed for code review before the shared package claims those capabilities.
3. **Improve the technical-review examples.** Replace the sampling-only linear example with a fitted end-to-end example and make the discrete example more informative.
4. **Treat fixed-graph fitting as the immediate product goal.** Graph comparison and discovery remain later extensions.
5. **Study uncertainty for nonlinear causal functionals.** Work should distinguish point identification, partial identification, regularity under the fitting loss, and numerical optimization uncertainty.
6. **Investigate projected or sliced distributional scores.** The team will examine whether they improve high-dimensional behavior.
7. **Explore PFNs at a bounded level.** A fixed graph or graph-as-input posterior approximator, possibly targeted directly at a causal quantity, is preferred to graph-as-output discovery.

## 10. Open questions

### Statistical and causal

- Under what assumptions are the causal functionals point identified, set identified, or unidentified for a supplied graph and observed margin?
- Which discrepancies make the target sufficiently smooth for stable estimation, asymptotic normality, or an influence-function calculation?
- How should sampling uncertainty, optimization error, and structural non-identification be separated in reported ranges?
- Can partial-identification searches be made sharp and reproducible with fit tolerances, restarts, and certified bounds?
- How should observational and interventional datasets with different observed variables be weighted in one fit?

### Loss functions and computation

- Does Sinkhorn's preliminary heavy-tail advantage persist in controlled comparisons?
- Which projected or sliced score has the best statistical and computational tradeoff in high dimensions?
- When should discrete models use exact enumeration, direct probabilities, continuous relaxation, or Gumbel-Softmax?
- How far can finite-state enumeration scale before factorized or approximate inference is required?

### Software design

- What should the dataset-to-model schema contain, and should it be a table adapter, a separate formula, or a typed data object?
- How should treatment, outcome, and observed-variable roles be passed to operators without hard-coded names?
- Which optimizer should each supported objective use, and what diagnostics establish convergence?
- Should standard causal designs have convenience wrappers, or should the project expose only the general graph interface?

### PFNs

- How can a scientifically meaningful prior over nonlinear structural functions be specified?
- Is the useful amortization unit a repeated fixed graph, a graph supplied as input, or a direct causal query?
- How should prior shift, simulator misspecification, and calibration be tested?
- Does direct approximation of a causal quantity retain enough information while avoiding the full parameter posterior?
- When is the up-front transformer training cost justified by repeated inference?
- What theoretical guarantee is realistic once graph variation and nonlinear functions are included?
